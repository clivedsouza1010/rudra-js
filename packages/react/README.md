# @rudra-js/react

This package is part of [rudra-js](https://rudrajs.com).

rudra-js is an open-source TypeScript library (MIT) you install from npm. A language model designs one product-recommendation block for a page in your shop, rudra-js checks it against your catalog, and React renders it.

It is not a hosted platform, a visual or low-code app builder, or a workspace you sign up for.

You can use this package to render a component spec with React 18 or 19. This spec is a description
of the block generated by
[`@rudra-js/core`](https://github.com/clivedsouza1010/rudra-js/tree/main/packages/core).

For more on [`RudraComponent`](https://rudrajs.com/reference/react/RudraComponent) and [`extendRegistry`](https://rudrajs.com/reference/react/extendRegistry), see the reference on rudrajs.com.

All the components are just plain functions with no hooks, state or effects. They can be rendered:

- with `renderToString`
- in a client-rendered app
- as Server Components, in a setup that supports them (like the Next.js App Router)

If you render on the server, the recommendations will be in the initial HTML response and won't need
any client JavaScript. They never show up late like a client-fetched recommendation rail does. Even
a crawler that doesn't run JavaScript reads the recommendations.

## Install

```sh
npm install @rudra-js/react@latest @rudra-js/core@latest @rudra-js/attested@latest react react-dom
```

You will need to use this same command to install or to upgrade, even if your app already uses
rudra-js.

- For an app with `@rudra-js/anthropic`, you have to add it to the command with `@latest` too.
- For an app with `@rudra-js/a2ui`, you have to use the install line in that package's README
  instead. It also names the two A2UI packages.

You have to keep `@latest` on all the `@rudra-js` packages. These packages are published together.
For each package, the peer ranges on the others start at its own version. With just a bare name, npm
will stay inside the range you already have in `package.json`. This means that without `@latest`, an
app on an older core can get an `ERESOLVE`.

You need to leave `react` and `react-dom` without a version. It's how npm and pnpm keep a React 18
app on 18. But do name both, because npm will then move each to the newest release in its range. In
React 19, a `react-dom` at a different version from `react` won't load.

`@rudra-js/core` and `react` are peer dependencies. Your spec comes from your copy of core. This
package's elements have to come from your app's copy of React. If two copies of core have
different types, `spec` or another prop can fail its type check. With two copies of React, React
can refuse to render the component tree.

`@rudra-js/attested` is core's peer dependency. npm and pnpm will add it for you, but Yarn won't.
Yarn will move a bare name to its latest version though, so with Yarn, leave `react` and
`react-dom` out of the command if your app already has React.

```tsx
import { RudraComponent } from '@rudra-js/react';

<RudraComponent spec={spec} products={catalog} locale="en-GB" />;
```

`spec` is the value returned by `createComponentGenerator().generate()`. `products` is your catalog.

## What comes from where

It's up to the model to decide the layout of the block and the words in it. All of the facts about a
product will be read from your catalog when the page is served. Anything the model wrote will be
rendered as escaped text.

| Decided by the model                                                | Decided by your catalog |
| ------------------------------------------------------------------- | ----------------------- |
| Which layout, in what order                                         | Every product title     |
| Tone, headline, the words in each block                             | Every price             |
| Only in per-shopper mode: which products, and how each is described | Every image and link    |

By default you get cohort mode: shoppers who look alike share a spec. In this mode, core will fill
in the products and their order for each request. It will also write the reason under each product
and drop any badge the model wrote. If you set `generation: 'per-shopper'`, the model will make
those picks itself. In both modes, it's the model that chooses the product a hero names. For the
full split, see
[What the model decides, by mode](https://github.com/clivedsouza1010/rudra-js/tree/main/packages/core#what-the-model-decides-by-mode).

There is no field in the spec for a title, a price, an image or a URL. Instead, the component will
look up each product in `products` by a SKU that core has already checked.

**Validate `products` with `productSchema` from `@rudra-js/core`**. It's the same schema that the
candidate products you sent to core have already passed. This prop is a second way for data to reach
the page.

`imageUrl` will end up in an `<img src>`. `productSchema` rejects a protocol-relative URL such as
`//evil.example/pixel.png`. It also rejects a `data:` URL. Because it reads a path the way a browser
does, it will also reject `/\evil.example/pixel.png` and the same trick written with a tab or a
newline in it. In a browser, all of these resolve to someone else's host. React will block a
`javascript:` URL on its own, but none of these.

If a price isn't a finite number, rendering will throw an error.

Any row with `isInStock: false` counts as a row that isn't there. Its cards are dropped. If a hero
names it, the hero will lose its link. If a bundle has it as a member, the bundle will disappear.
Core will only name products that were in stock in the data you sent it. But this catalog is read
later, so it may be the fresher of the two.

## Styling

This package doesn't ship any CSS. Without styles, the block will render as a single run-on line.
All of the card elements are inline. This means a card's parts sit on a single line with spaces in
between. There is nothing to separate a card from the next. You style it from there.

For a working stylesheet, see `examples/shop/public/demo-styles.css`. It uses just the classes in
the table below. You can copy it as a starting point. It isn't a supported API though. The example
shop applies it by default. You can use `?styles=off` to see the raw markup.

All of the elements the component renders have a class. Here is the full list:

| Where          | Classes                                                                                                                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The wrapper    | `.rudra`, `.rudra__header`, `.rudra__headline`, `.rudra__subheadline`, `.rudra__rationale`                                                                                                                 |
| A hero         | `.rudra-hero`, `.rudra-hero__headline`, `.rudra-hero__body`, `.rudra-hero__link`, `.rudra-hero__price`, `.rudra-hero__cta`                                                                                 |
| A grid         | `.rudra-grid`, `.rudra-grid__title`, `.rudra-grid__items`                                                                                                                                                  |
| A carousel     | `.rudra-carousel`, `.rudra-carousel__title`, `.rudra-carousel__track`                                                                                                                                      |
| A banner       | `.rudra-banner`, `.rudra-banner__text`, `.rudra-banner__cta`                                                                                                                                               |
| A copy block   | `.rudra-copy`, `.rudra-copy__title`, `.rudra-copy__body`                                                                                                                                                   |
| A bundle       | `.rudra-bundle`, `.rudra-bundle__label`, `.rudra-bundle__title`, `.rudra-bundle__body`, `.rudra-bundle__items`, `.rudra-bundle__item`, `.rudra-bundle__link`, `.rudra-bundle__price`, `.rudra-bundle__cta` |
| A product card | `.rudra-card`, `.rudra-card--featured`, `.rudra-card__image`, `.rudra-card__body`, `.rudra-card__title`, `.rudra-card__price`, `.rudra-card__reason`, `.rudra-card__badge`                                 |

A few notes on those:

- `.rudra__rationale` appears only under `hasDiagnostics`.
- `.rudra-bundle__label` holds your name for the set. It will only show up for a bundle you gave a
  `label`.
- Your `className` will be added alongside `rudra`, never in place of it, to keep the child classes
  working.
- `.rudra-carousel__track` is meant to scroll horizontally, so give it `overflow-x: auto`. There is
  no JavaScript to scroll it for you.
- `.rudra-card--featured` is applied alongside `.rudra-card`. Write the `.rudra-card--featured { ... }`
  rule after the base rule to layer it on top.

`.rudra-banner__cta` and `.rudra-bundle__cta` are plain text. They are not links or buttons. Don't
style them as buttons unless a renderer of your own wraps them in one. For the hero, the call to
action sits inside the product link. This means the hero's call to action is clickable.

All of the cards in a carousel are links. If you tab from card to card, the track will scroll. This
way you can use the carousel by keyboard, even with the scrollbar hidden.

### Attributes

In the markup you will also find the model's decisions. You can use these attributes for styling or
analytics.

| Attribute                | On                             | Value                                                      |
| ------------------------ | ------------------------------ | ---------------------------------------------------------- |
| `data-rudra-slot`        | the wrapper                    | The slot the spec was generated for                        |
| `data-rudra-source`      | the wrapper                    | `llm`, `cache` or `fallback`                               |
| `data-rudra-tone`        | the wrapper                    | The tone the model chose for the component                 |
| `data-rudra-banner-tone` | a banner                       | A banner's own tone, a different vocabulary from the above |
| `data-rudra-columns`     | a grid                         | The column count the model chose                           |
| `data-rudra-sku`         | a card, hero link, bundle item | The product, for click attribution                         |
| `data-rudra-basis`       | a card                         | Why the product was picked: `most_viewed`, `popular`, …    |

`data-rudra-source` is always there. This lets you read the cache hit rate and the fallback share
directly from a rendered page. Anything more specific will only appear under `hasDiagnostics`,
because it tells a visitor what you run and when it's failing:

| Attribute               | On          | Value                                                                                                                  |
| ----------------------- | ----------- | ---------------------------------------------------------------------------------------------------------------------- |
| `data-rudra-provider`   | the wrapper | The model vendor, or `none`                                                                                            |
| `data-rudra-model`      | the wrapper | The model name, or `none`                                                                                              |
| `data-rudra-latency-ms` | the wrapper | How long generation took                                                                                               |
| `data-rudra-degraded`   | the wrapper | Why it fell back: `no-provider`, `provider-error`, `timeout`, `invalid-generation`, `unusable-on-serve` or `requested` |

## Replacing a renderer

You can swap any block's renderer for a component from your design system. Only the drawing changes.
Neither the spec nor the block kinds the model picks from will change.

```tsx
import { RudraComponent, extendRegistry } from '@rudra-js/react';

const registry = extendRegistry({
  grid: ({ block, context }) => <MyProductGrid items={block.items} context={context} />,
});

<RudraComponent spec={spec} products={catalog} registry={registry} />;
```

If a grid, carousel or bundle block has nothing left in your catalog, it will be dropped before any
renderer runs, yours or ours. But the rest of the blocks will still render. Banner and copy blocks
will always reach the renderer because they don't depend on the catalog. Heroes without a headline
or body will need an in-stock SKU in your catalog to get there.

## Props

| Prop                | Notes                                                                                                                                                                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spec`              | Required. From `@rudra-js/core`.                                                                                                                                                                                                               |
| `products`          | Required. A list of products, or anything keyed by SKU. See below, and the `productSchema` warning above.                                                                                                                                      |
| `bundles`           | The sets your shop sells together. Only needed if a spec can carry a bundle block.                                                                                                                                                             |
| `registry`          | Replaces some or all of the block renderers.                                                                                                                                                                                                   |
| `hrefForSku`        | Defaults to `/product/{sku}`, URL-encoded.                                                                                                                                                                                                     |
| `formatPrice`       | Formats product prices, not bundle prices. Defaults to `Intl.NumberFormat`, which knows how many decimal places each currency wants.                                                                                                           |
| `formatBundlePrice` | Formats a bundle's own price, in the currency the shop put on the set. Defaults to `Intl.NumberFormat`, like `formatPrice`. The price and its currency come from the same bundle object, so members priced in another currency change nothing. |
| `locale`            | Sets how prices are punctuated. Defaults to the **server's** locale, which is rarely the shopper's. Pass it if you serve more than one locale.                                                                                                 |
| `hasDiagnostics`    | Adds the provider, the model name, the latency and the model's own reasoning to the markup. Off by default.                                                                                                                                    |
| `className`         | Added alongside `rudra`.                                                                                                                                                                                                                       |

### What `products` may be

`products` has to be a list of products, or anything keyed by SKU that answers `get(sku)` and
`has(sku)`. This means you can use a `Map` or your own index. The renderers will only ever call
`get`. `has` is how the component tells a keyed catalog from a list. If your catalog is too big to
copy into a `Map` on every request, pass a view of your store instead. This prop is typed as a
`ReadonlyMap`. In TypeScript that means your view has to either implement `ReadonlyMap` or be cast
with `as unknown as ReadonlyMap<string, Product>`.

You can also pass a `Map` from a worker or a `node:vm` sandbox, even though it fails
`instanceof Map`.

Anything that is neither a list nor keyed will be refused right away, with an error that names the
prop. This covers a `Set` of products, a plain object or a `Map` that has been through JSON.

If there's nothing left to show, the component will render nothing at all. This covers a spec with
no blocks. It also covers a spec whose products have all left your catalog since it was generated.

### What `bundles` is

`bundles` is a list of the sets your shop sells together, just like `products` is your catalog. As
for the model, it will only ask for a bundle block. It never invents a set and it never sees a
price.

You offer the sets, but it's core that picks which set fills each bundle block. It does this in
`reconcileSpec` as the page is served, after the spec was generated. It goes by what this shopper
has in their basket, has looked at or is browsing right now. After this, the spec will carry the id
of the set core picked. You supply the rest with this prop (the set's members, its price, the
currency of that price and your name for it) to give the component something to draw.

**Validate `bundles` with `bundleSchema` from `@rudra-js/core` and pass the same list you sent to
`parseTrackingInput`.** It's the list core checked before it picked a set:

- every member is in stock
- no member is one the shopper disliked
- no member is the product the shopper is viewing
- no product shows up twice
- the whole set fits in what's left of `context.maxItems`, the most products the component may show

After that, core will only give the renderer the id it chose. If you pass a stale or different list
here, you'll draw a set that none of those checks saw, under an id that was checked against another
list.
